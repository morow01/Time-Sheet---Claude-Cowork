App Purpose

The Resource Availability Planner is intended to answer one practical question:

Who is the right technician/contact for this exchange or cabinet fault, and are they available on the selected date?

The app should not simply return the nearest person in Ireland. It should consider where the fault is, where each technician normally works, where they start from, and whether they are available according to the tracker.

Import Strategy

The Excel file will change throughout the year, so the app should allow contacts and tracker availability to be imported separately.

Import Contacts

Reads only the CFE Contacts sheet from the selected workbook.

  • Replace or update contact database
  • Show number of contacts imported
  • Show missing staff numbers
  • Show missing work locations
  • Show real emails detected
  • Show contacts changed since previous import

Import 2026 Tracker

Reads only the 2026 Tracker sheet from the selected workbook.

  • Replace or update availability data
  • Show detected date range
  • Show number of technicians imported
  • Show unmatched technician names
  • Show status code counts
  • Show unknown status codes

Separate imports are important because contact details may change less often than the daily availability tracker.

Extraction Logic

Extracting CFE Contacts

  1. Find the sheet named CFE Contacts.
  2. Read row 1 as headers.
  3. Map columns by header name, not by fixed column letter.
  4. For each non-empty row, read manager, name, staff number, mobile, raw email field, role, home/start location, and work locations.
  5. Clean mobile number spacing.
  6. Only treat eMailAddr as a real email if it contains @.
  7. Store the raw email field separately.
  8. Save normalized contacts.

Extracting 2026 Tracker

  1. Find the sheet named 2026 Tracker.
  2. Read date columns from row 6, starting at column D.
  3. Stop when there are no more valid date cells.
  4. For each technician row, read SOM from column A, tracker area/comment from column B, and technician name from column C.
  5. If SOM is blank, inherit the previous SOM above it.
  6. Skip empty/non-technician rows.
  7. Read each date cell as the technician's status for that date.
  8. Normalize inconsistent status casing.
  9. Join tracker rows to contacts by technician name.
  10. Report fuzzy-name mismatches for manual review.

Matching Strategy

Matching should be careful because the closest technician is not always the correct technician. The app should separate eligibility from distance.

Strong Match

The exchange/cabinet town, county, area, or mapped exchange group matches the technician's work locations.

Best candidate

Possible Match

The technician is nearby, in the same broad region, or under the same SOM group, but the area match is not exact.

Review needed

Nearby But Outside Area

The technician may be geographically close but their work locations do not indicate responsibility for that area.

Do not auto-recommend

Candidate Logic

1. Find selected exchange/cabinet coordinates and area details.
2. Compare fault area against each technician's Work Locations.
3. Join technician to tracker status for selected date.
4. Keep everyone visible at first, but badge their status and match quality.
5. Rank strong area matches above distance-only matches.
6. Use distance as a ranking helper, not the main rule.

Map Plan

The map should show Ireland with pins for exchanges, cabinets, selected fault location, and staff start locations.

Pin Type Source Purpose
Exchange pin Main Rian exchange database Search target and fault location
Cabinet pin Main Rian cabinet database More precise fault location where available
Staff pin CFE Contacts: Home / Start Location Approximate start point for travel/distance
Highlighted candidate pin Search result ranking Show recommended or relevant technicians

Staff pins should be treated as approximate unless the start location can be mapped to a precise exchange, building, or coordinate.

Known Data Issues

  • eMailAddr is not reliably an email field. It usually contains a name, but a few real emails exist.
  • Some contact names differ from tracker names, so the join needs alias/fuzzy matching.
  • Work Locations can be a broad region or multiple places, not one exact coordinate.
  • Home / Start Location may be blank for some people.
  • Some staff are in contacts but not tracker, and some tracker names are not in contacts.
  • Status codes have inconsistent casing, such as oc, OFF, WTt, and wtt.

Recommended First Version

The first useful version should focus on importing data, searching a fault location, and showing ranked candidates with clear match/status badges.

1

Build Data Import

Import CFE Contacts and 2026 Tracker separately from the latest Excel file.

2

Build Search

Search exchange/cabinet database and select the fault location.

3

Show Everyone First

Display all contacts initially, with status and match badges, before hiding anyone behind strict filters.

4

Add Filters

Add filters for All, Available only, SA only, SA/OC/50, On Call only, and Unavailable hidden.

5

Add Manual Mapping

Allow corrections for name aliases, area mappings, and staff start-location coordinates.

The key design rule: Home / Start Location is for travel distance, Work Locations is for eligibility, and tracker status is for availability.
